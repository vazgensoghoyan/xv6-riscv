# ext2 tools lab

## Сборка

Требуется `gcc` и стандартные утилиты POSIX.

```bash
make
```

После сборки будут доступны утилиты:
- `sb_info` — информация о superblock
- `inode_info` — метаданные inode и блоки
- `inode_cat` — вывод содержимого inode в stdout
- `inode_dir` — вывод содержимого каталога (inode → name)

## Очистка сборки

```bash
make clean
```

## Запуск тестов

Тестовый сценарий создаёт ext2 image, наполняет его файлами и проверяет корректность работы утилит.

```bash
make test
```

или

```bash
bash tests/test.sh
```

## Тестовый сценарий (tests/test.sh)

Скрипт `tests/test.sh` выполняет полный интеграционный тест всех утилит на реальной ext2 файловой системе.

### Что делает тест:

1. **Создание образа файловой системы**
   - создаётся sparse image (`truncate`)
   - форматируется в ext2 (`mkfs.ext2`)
   - используется нестандартный размер блока (2KB)
   - задаётся фиксированное количество inode

2. **Монтирование файловой системы**
   - image подключается через loop device (`losetup`)
   - монтируется в каталог через `mount`

3. **Создание тестовых данных**
   Внутри файловой системы создаются:
   - обычный текстовый файл (`small.txt`)
   - большой файл (`big.bin`)
   - разреженный файл большого размера (`sparse_huge.bin`)
   - несколько директорий и вложенных подкаталогов

4. **Сбор контрольных данных**
   - вычисляются inode всех созданных файлов (`stat`)
   - считаются контрольные суммы SHA-512 (для полного файла и частично для sparse-файла)

5. **Размонтирование**
   - файловая система отмонтируется
   - loop device отключается

6. **Проверка утилит**
   - `sb_info` проверяет superblock (magic, block size)
   - `inode_info` проверяет корректность чтения inode и блоков
   - `inode_cat` сравнивает вывод с эталонным SHA-512
   - `inode_dir` проверяет разбор каталогов

7. **Проверка через loop device**
   - проверяется, что утилиты корректно работают не только с образом файла, но и с блочным устройством `/dev/loopX`
